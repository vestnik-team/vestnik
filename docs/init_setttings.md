# Начальные настройки OJS

При запуске контейнера `ojs` Docker Compose дожидается готовности MariaDB и запускает `docker/entrypoint.sh`. До старта Apache этот скрипт подключает перечисленные в нём плагины и вызывает `docker/bootstrap.php`. Bootstrap читает параметры из окружения, применяет `docker/config.inc.php.template`, записывает `/var/www/html/config.inc.php` и регистрирует новые плагины. Файл конфигурации хранится в томе `ojs_app`.

## Только при первой установке

Если база пуста, скрипт вызывает штатный установщик OJS. Он создаёт таблицы и учётную запись администратора сайта. Журнал «Вестник НГУ», его разделы, роли редакции и тестовые статьи настраиваются отдельно в задаче № 35.

| Настройка | Что получит участник |
|---|---|
| Языки сайта | Основной — русский (`ru`), дополнительный — английский (`en`). |
| Часовой пояс | `Asia/Novosibirsk`. |
| Администратор сайта | Логин из `OJS_ADMIN_USER`, по умолчанию `admin`. Почта из `OJS_ADMIN_EMAIL`, по умолчанию `admin@example.test`. |
| Пароль администратора | Значение `OJS_ADMIN_PASSWORD` длиной от 8 символов. Пароль нужен для входа через браузер. |
| Маяк PKP | Выключен (`enableBeacon = false`). |
| Идентификатор хранилища OAI | `ojs.` и имя хоста из `OJS_BASE_URL`. Например, для `http://localhost:8080` получится `ojs.localhost`. |
| Ключи установки | Bootstrap генерирует случайные `security.salt` и `security.api_key_secret`. Если `general.app_key` пуст, bootstrap задаёт начальный ключ, а установщик OJS записывает постоянный. |

После успешной установки скрипт выводит `OJS installed. Sign in with the administrator account from .env.` При следующих запусках сохраняются ключи и существующая учётная запись. Для смены пароля уже созданного администратора используйте OJS. Изменение `OJS_ADMIN_PASSWORD` в `.env` действует только при новой установке.

## При каждом запуске контейнера

Значения в таблице переносятся в рабочий `config.inc.php`. Если нужно изменить одно из них, обновите `.env` и снова выполните `sh start.sh` из корня проекта. Скрипт запуска вызывает `docker compose up -d`, и Compose применяет изменённое окружение.

| Раздел и поле в config.inc.php | Источник и поведение |
|---|---|
| `[general] base_url` | Адрес сайта из `OJS_BASE_URL`, включая схему и порт. |
| `[general] allowed_hosts` | Один разрешённый хост из этого адреса, без схемы и порта. |
| `[database] driver` | `mysqli` для подключения к MariaDB. |
| `[database] host`, `port` | `OJS_DB_HOST` и `OJS_DB_PORT`. По умолчанию Compose передаёт `db` и `3306`. |
| `[database] name`, `username`, `password` | `OJS_DB_NAME`, `OJS_DB_USER` и `OJS_DB_PASSWORD` соответственно. Пароль `DB_ROOT_PASSWORD` использует только контейнер MariaDB. |
| `[files] files_dir` | `/var/www/files` внутри контейнера. К этому пути подключён том `ojs_files` для загружаемых файлов. |
| `[email] default` | При заполненном `SMTP_HOST` выбирается `smtp`. При пустом — `log`, и письма записываются в журнал. |
| `[email] smtp_server`, `smtp_port` | `SMTP_HOST` и `SMTP_PORT`. Если порт пуст, bootstrap использует `25`. |
| `[email] smtp_username`, `smtp_password` | `SMTP_USER` и `SMTP_PASSWORD`. Для локального запуска без отправки писем их можно оставить пустыми. |

Для существующей установки bootstrap проверяет доступ к записи сайта в базе, применяет настройки и выводит `Existing OJS installation is ready.` Если OJS помечена как неустановленная, а в базе уже есть таблицы, скрипт останавливается и предлагает проверить тома приложения и базы.

## Где посмотреть реализацию

- [docker/entrypoint.sh](../docker/entrypoint.sh) — список плагинов и порядок запуска контейнера.
- [docker/bootstrap.php](../docker/bootstrap.php) — проверка состояния, вызов установщика, применение настроек и регистрация плагинов.
- [docker/config.inc.php.template](../docker/config.inc.php.template) — поля конфигурации, которыми управляет bootstrap.
- [docker-compose.yml](../docker-compose.yml) — переменные окружения, их значения по умолчанию, тома и опубликованный порт.
