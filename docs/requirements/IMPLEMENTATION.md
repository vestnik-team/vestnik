# Требования к реализации и проверке

## 1. Отсутствующие функциональные возможности

| Требование | Формулировка | BR | Покрытие / недостающая часть |
|---|---|---|---|
| [FR-3.2](FR.md) | Система должна формировать список рекомендуемых рецензентов на основании соответствия **тегов** статьи областям их компетенций. | BR-08 | `-` |
| [FR-3.3](FR.md) | Система должна показывать редактору **основания рекомендации** каждого кандидата, включая совпавшие **теги**. | BR-08, BR-09 | `-` |
| [FR-3.6](FR.md) | Система должна учитывать текущую **загрузку кандидатов** при формировании рекомендаций рецензентов. | BR-08 | `-` |
| [FR-4.2](FR.md) | Система должна позволять кандидату принять или отклонить приглашение через электронную **почту** без обязательного входа в веб-интерфейс. | BR-02 | `-` |
| [FR-4.6](FR.md) | Система должна позволять редактору задавать **последовательность** приглашения выбранных кандидатов и автоматически направлять следующее приглашение при отказе или истечении срока ответа. | BR-06, BR-09, BR-11 | `-` |
| [FR-5.3](FR.md) | Система должна позволять рецензенту направлять рецензию, рекомендацию и приложения через электронную **почту** без обязательного входа в веб-интерфейс. | BR-02 | `-` |
| [FR-7.1](FR.md) | Система должна позволять автору направлять новую версию рукописи и ответ на замечания через электронную **почту**. | BR-01, BR-02 | `-` |
| [FR-7.5](FR.md) | Система должна позволять автору связывать ответы на **замечания** с конкретными пунктами рецензии, а редактору — отмечать результат их проверки. | BR-12 | `-` |
| [FR-8.2](FR.md) | Система должна позволять участникам обмениваться отредактированными версиями и замечаниями через электронную **почту** с сохранением материалов в подаче. | BR-01, BR-02 | `-` |
| [FR-10.2](FR.md) | Система должна позволять автору подтвердить согласование файлов либо направить замечания через электронную **почту**. | BR-02 | `-` |
| [FR-G.4](FR.md) | Система должна связывать входящие письма и вложения с соответствующими статьями и сохранять **историю переписки**. | BR-02, BR-12 | `-` |
| [FR-G.5](FR.md) | Система должна проверять личность и полномочия отправителя перед выполнением действия, полученного через электронную **почту**. | BR-02, BR-05 | `-` |

## 2. Частично поддержанные функциональные требования

| Требование | Формулировка | BR | Покрытие / недостающая часть |
|---|---|---|---|
| [FR-3.1](FR.md) | Система должна позволять указывать тематические **теги** статьи и области компетенций рецензентов с использованием общего справочника тегов. | BR-08 | `+-` (есть ключевые слова и интересы; нужен общий справочник) |
| [FR-3.4](FR.md) | Система должна позволять редактору выбирать кандидатов из **рекомендаций** либо вручную и подтверждать их приглашение. | BR-05, BR-09 | `+-` (есть ручной выбор; нет рекомендаций по тегам) |
| [FR-3.5](FR.md) | Система должна показывать текущую **загрузку кандидата**: количество ожидающих ответа приглашений и незавершённых рецензий. | BR-08 | `+-` (есть данные о назначениях; проверить состав показателей) |
| [FR-4.3](FR.md) | Система должна отображать **состояние** каждого **приглашения**: ожидается ответ, принято, отклонено или срок ответа истёк. | BR-01, BR-06 | `+-` (есть ответы и сроки; проверить статус просрочки) |
| [FR-4.5](FR.md) | Система должна показывать **количество** согласившихся **рецензентов** и его соответствие количеству, установленному правилами журнала. | BR-06 | `+-` (есть список рецензентов; нужна проверка нормы) |
| [FR-5.2](FR.md) | Система должна исключать сведения, подлежащие сокрытию согласно модели **слепого рецензирования**, из доступных рецензенту метаданных, писем и названий файлов. | BR-07 | `+-` (есть анонимный режим; проверить письма и имена файлов) |
| [FR-5.5](FR.md) | Система должна показывать редактору количество полученных рецензий и его **соответствие требованиям** журнала. | BR-06 | `+-` (есть полученные отзывы; нужна проверка нормы) |
| [FR-5.6](FR.md) | Система должна **скрывать личность** рецензента при передаче автору отзывов и приложений в соответствии с моделью слепого рецензирования. | BR-07 | `+-` (есть анонимный режим; файлы требуют проверки) |
| [FR-9.2](FR.md) | Система должна связывать публикационные файлы с соответствующей статьёй и сохранять их **версии** при замене. | BR-01, BR-12 | `+-` (есть хранение файлов; проверить историю замен) |
| [FR-9.4](FR.md) | Система должна поддерживать преобразование рукописей DOCX и LaTeX в **JATS XM**L и подготовку **PDF** с сохранением исходных файлов. | BR-13 | `+-` (есть загрузка файлов; нужен конвейер конвертации) |
| [FR-9.5](FR.md) | Система должна проверять полученный **JATS XML** на соответствие согласованной **схеме** и предоставлять отчёт об ошибках. | BR-13 | `+-` (есть работа с XML; нужен валидатор и отчёт) |
| [FR-10.1](FR.md) | Система должна направлять автору публикационные файлы для проверки по **электронной почте**. | BR-01, BR-02 | `+-` (есть письма автору; проверить отправку самих файлов) |
| [FR-10.3](FR.md) | Система должна сохранять результат авторской корректуры с привязкой к проверенной версии публикационных файлов. | BR-01, BR-04, BR-12 | `+-` (есть обсуждения; нужно **явное согласование** версии) |
| [FR-G.2](FR.md) | Система должна **запрещать** **переходы между состояниями статьи**, отсутствующие в согласованной схеме переходов. | BR-04 | `+-` (есть штатные этапы; проверить ограничения переходов) |
| [FR-G.6](FR.md) | Система должна поддерживать **импорт** согласованного состава существующих данных с сохранением связей между материалами, авторами, статьями и выпусками. | BR-03 | `+-` (есть импорт XML; нужен перенос из нашего источника) |
| [FR-G.7](FR.md) | Система должна формировать отчёт об **импорте** с перечнем перенесённых объектов, ошибок и неперенесённых записей. | BR-03 | `+-` (есть ошибки импорта; нужен полный отчёт сверки) |
| [FR-G.8](FR.md) | Система должна предоставлять редактору **список статей** с текущим этапом, ответственным участником, ближайшим сроком и **продолжительностью** нахождения на этапе. | BR-11 | `+-` (есть список подач; нужны сроки и время на этапе) |
| [FR-G.9](FR.md) | Система должна выделять статьи с **нарушенными сроками** и позволять переходить к действию, необходимому для продолжения обработки. | BR-11 | `+-` (есть сроки рецензий; нужен общий контроль задержек) |
| [FR-G.10](FR.md) | Система должна формировать историю обработки статьи с событиями подачи версий, назначения участников, получения рецензий и принятия решений. | BR-12 | `+-` (есть журнал событий; проверить **полноту истории**) |
